the product

A week you can read

Keyboard-first. High density. One session at a time. Built to answer a simple question: where did the hours go.

/timer

One active session

Start or stop. While idle, the note suggests earlier tasks.

/dashboard

The week in bars

Today’s total, current focus, the week in bars.

/insights

When, not only how much

The timeline card on Insights shows when the time was logged and how it spread across days and projects. One card, two toggles. Select a view.

days

One row per day. Each session sits where it fell on the clock; overlaps take sub-lanes. The day total is on the right.

  • Sessions split at local midnight. The live one grows to now.
  • Working hours or 24h, for all three views.
  • Over 62 days, only Rhythm. A year of bars is not readable.
  • A past range reads its own window, GET /sessions?from&to, not the whole history.
  • One SVG path per project colour keeps the longest main-thread task under 200 ms.

around every screen

  • A live session puts ▶ HH:MM:SS in the tab title and a dot on the icon.
  • Tabs share writes. Another device catches up when you look at it.
  • A session past the reminder threshold asks to keep going or stop.
  • The daily URL installs as an app. It still needs the API.

Agents write. I review. The product still has to work.

I did not write every line by hand. The docs did the steering.

  1. 01 plan

    Agents help shape the work. I decide what ships. Design tokens, brand, and the session model stay human decisions.

  2. 02 implement

    Agents write most of the code. The stack does not change for convenience: SvelteKit, TypeScript, Go, the same dark IDE chrome.

  3. 03 review

    I read the diff. If it would not survive a workday on the timer, it does not land. Agent output is held to the same rules as everything else.
